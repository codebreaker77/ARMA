# ARMA Offline Evaluation Protocol: System 1 Metacognitive Features

This protocol governs the empirical evaluation of candidate "System 1" metacognitive and speculative execution features for the ARMA layer using public agent trajectories.

---

## 1. Dataset & Provenance

- **Dataset**: `nebius/SWE-rebench-openhands-trajectories` (Qwen3-Coder-480B + OpenHands)
- **Pinned Revision**: `35455389ab51bf5e2306bfd436ef72d0f98bf882`
- **Total Population**: 67,074 trajectories across 1,823 repositories.
- **Evaluation Sample Size**: $N = 2,000$ trajectories, deterministically sampled and stratified across repositories (`seed=42`).
- **Data Splitting**:
  - Split is strictly partitioned **BY REPOSITORY** using the deterministic SHA-256 hash of the canonical repo string:
    $$\text{hash\_val} = \text{int}(\text{sha256}(\text{repo}).\text{hexdigest}(), 16) \pmod{1000}$$
    - **Dev Split (70%)**: $\text{hash\_val} < 700$
    - **Frozen Test Split (30%)**: $\text{hash\_val} \ge 700$
  - Invariant: Zero repository overlap between Dev and Test. Hyperparameters, feature schemas, and decision thresholds are established solely on the Dev split. The Frozen Test split is evaluated exactly once at the conclusion of each experiment.

---

## 2. Field Classification & Leakage Boundary

Each field in the raw dataset schema is strictly classified to prevent data leakage:

| Field Name | Type | Classification | Usage Rules |
| :--- | :--- | :--- | :--- |
| `trajectory_id` | String | Identifier | Metadata only. Never used as a feature. |
| `instance_id` | String | Identifier | Metadata only. Never used as a feature. |
| `repo` | String | Identifier / Grouping | Used exclusively for repo-level splitting, GroupKFold, and cluster bootstrap. Never an input feature. |
| `tools` | List | OBSERVABLE-AT-STEP-$t$ | Available tool schemas presented to the agent. |
| `trajectory[:t]` | List | OBSERVABLE-AT-STEP-$t$ | Observable prefix up to step $t$ (messages, tool calls, tool stdout/stderr). |
| `trajectory[t:]` | List | OUTCOME / FORBIDDEN | Future steps beyond step $t$. Strictly forbidden for feature calculation at step $t$. |
| `model_patch` | String | OUTCOME / FORBIDDEN | Final patch generated by agent. Forbidden. |
| `exit_status` | String | OUTCOME / FORBIDDEN | Process exit status after run. Forbidden. |
| `resolved` | Integer | OUTCOME / LABEL ONLY | Ground truth binary outcome ($1 = \text{resolved}, 0 = \text{unresolved}$). Used ONLY as a prediction target / label. Forbidden as a feature. |
| `gen_tests_correct` | Float | OUTCOME / FORBIDDEN | Post-hoc benchmark test metric. Forbidden. |
| `pred_passes_gen_tests`| Float | OUTCOME / FORBIDDEN | Post-hoc benchmark test metric. Forbidden. |

## 3. Mandatory Leakage Guards & Controls

No experimental result counts toward decision thresholds unless all leakage guards pass:

1. **Suffix-Invariance Test (Unit Test)**:
   - For randomly sampled $(\text{trajectory}, t)$ pairs, replace all elements in `trajectory[t:]` with arbitrary garbage text, corrupted commands, or randomized synthetic messages.
   - The feature vector computed at step $t$ must be bit-for-bit identical before and after corruption.
2. **Label-Shuffle Control**:
   - Randomly permute the `resolved` label across trajectories within repository groups.
   - Model AUROC under shuffled labels must collapse to $0.50 \pm \text{CI}$. Any model exhibiting AUROC significantly different from 0.50 under label shuffle fails validation due to implicit target leakage.
3. **Dumb Baselines**:
   - Every predictive model must be reported against two naive non-cognitive baselines:
     - Baseline A: Prefix length only (character count or token count up to step $t$).
     - Baseline B: Step index only ($t$).
4. **Epistemic Invariant**:
   - Results are never reported as "leak-free" or "proven". Reports must explicitly document which guards were evaluated and their empirical outputs.

---

## 4. Statistical Estimation & Token Accounting

- **Confidence Intervals (CIs)**:
  - All reported uncertainty intervals are 95% confidence intervals computed via **Cluster Bootstrap by Repository** with 1,000 resamples.
  - Sample size $n$ (both trajectory count and repository count) must be reported alongside every metric.
- **Token Proxy**:
  - Token counts are computed using `tiktoken` with encoding `cl100k_base`.
  - Every token metric is explicitly labeled as **"estimate"** to reflect tokenizer proxy assumptions.
- **Execution Constraints**:
  - Deterministic seeds (`seed=42`).
  - Single command per experiment.
  - CPU-only execution; zero paid or external API dependencies.

## 5. Experiment Specifications & Decision Thresholds

### Phase 1: Action Taxonomy (E0)
- Tool calls normalized into 4 mutually exclusive classes:
  - `read_only`: `cat`, `head`, `tail`, `ls`, `find`, `grep`, `sed -n`, `view`, `git diff/log/status`, file viewing.
  - `test_run`: `pytest`, `unittest`, `tox`, `python -m unittest`, custom test runners.
  - `edit`: `str_replace_editor`, `sed -i`, `patch`, `git apply`, file creation/overwrites.
  - `other`: environment setup, package install, git branch/checkout, monologue/think, task_tracker, finish.
- **Validation**: 100 randomly sampled steps exported to `sample_for_human_labels.csv`. Evaluator agreement must be $\ge 95\%$ before proceeding.

### Phase 2: Loop Census (E1) & Step-Type Census (E2)
- **E1 Exact Loop Patterns**:
  - Identical action + observation $\ge 4$ repetitions.
  - Identical action + error $\ge 3$ repetitions.
  - Monologue (no tool calls) $\ge 3$ consecutive assistant steps.
  - Alternating $A, B \ge 6$ cycles.
- **E1 Semantic Loop Patterns**:
  - *Edit-revert*: File content state returns to an earlier observed hash state.
  - *Failing-test stall*: Same failing test IDs observed $\ge 3$ times with no intervening edit to the target module.
  - *Repeated read*: Same file path re-read $\ge 3$ times with no intervening edit or test execution.
- **E1 Simulated Cut Policy**:
  - Terminate trajectory at first detected loop plus grace period $g \in \{0, 3, 5\}$.
  - Compute tokens saved, resolved runs wrongly cut, and cost per resolved task:
    $$\text{Cost per Resolved Task} = \frac{\text{Total Tokens}}{\text{Resolved Tasks} - \text{Wrongly Cut Resolved Tasks}}$$
- **E1 Decision Threshold**:
  - **Pursue Loop Recovery** only if loops account for $\ge 10\%$ of tokens in unresolved runs **AND** the cut policy loses $\le 2\%$ of resolved runs.
- **E2 Step-Type Census & Routing Upper Bound**:
  - Measure step share and estimated token cost share by class.
  - Routable-cost upper bound:
    $$\text{Routable Cost Share} = \text{CostShare}(\text{read\_only} + \text{test\_run}) \times (1 - r)$$
    for cheap-tier price ratios $r \in \{0.10, 0.25\}$.
  - Cache-aware variant: Account for prompt cache invalidation penalties when switching between heterogeneous model endpoints.
- **E2 Decision Threshold**:
  - **Pursue Tier Routing** only if routable share of cost is $\ge 40\%$.

### Phase 3: Next-Read Prediction & Speculation (E3)
- Given trajectory prefix before step $t$, predict target command and file when true next action is `read_only`.
- Baselines:
  1. File named in last traceback/error.
  2. Most recent file path in last observation.
  3. Top grep hit in observation.
  4. Class-frequency prior.
- Metrics: Top-1 and Top-3 accuracy at command+target level and at file level.
- Analysis:
  - (a) Tool-result prefetch only (cheap, executes deterministic read tool, no extra LLM call).
  - (b) Full speculation (pre-launches next speculative LLM call; miss penalizes $(1 - \text{hit}) \times \text{call\_cost}$).
- **E3 Decision Threshold**:
  - **Pursue Full Speculation (b)** only if Top-1 hit rate is $\ge 50\%$ or misses are provably cheap; otherwise restrict scope to **Tool Prefetch (a) only**.

### Phase 4: Stuck Predictor v2 (E4)
- Prefix-only feature extraction at steps $t \in \{10, 20, 30, 40\}$.
- Features: action-class counts, distinct files touched, edit count, edit-revert count, repeated command count, test-run count, failing-test set stability, tokens consumed so far, mean observation length, first-edit step index, repro script existence.
- Cross-Validation: GroupKFold by repository on Dev split.
- Models: L2 Logistic Regression and Gradient Boosted Trees.
- Metrics: AUROC with cluster bootstrap CI, Expected Calibration Error (ECE), and terminate-policy simulation.
- **E4 Decision Threshold**:
  - **Pursue Stuck Predictor** only if AUROC is $\ge 0.70$ at $t=30$ with lower 95% CI $\ge 0.65$, **AND** the terminate policy preserves $\ge 98\%$ of resolved runs while saving $\ge 15\%$ of total tokens.
